[[introduction]]
== Introduction

Spexflix Server's API is xref:graphql-api-guide.adoc[GraphQL].
A few endpoints are plain HTTP, for what GraphQL does not suit: posters, subtitle files and resumable uploads.
Like GraphQL, they are thin adapters over the services, which decide who may do what.
Video is never served by Spexflix Server, but by the <<media_server,media server>>.

[[http_verbs]]
== HTTP verbs

|===
| Verb | Usage

| `GET`
| Used to retrieve a poster

| `HEAD`
| Used to read an upload's offset

| `POST`
| Used to upload a poster or subtitles, or to create an upload

| `PATCH`
| Used to send a chunk of an upload

| `DELETE`
| Used to cancel an upload

| `OPTIONS`
| Used to read the upload endpoint's capabilities
|===

[[http_status_codes]]
== HTTP status codes

|===
| Status code | Usage

| `200 OK`
| The request completed successfully.

| `201 Created`
| An upload has been created.

| `204 No Content`
| There is nothing to return, e.g. a chunk has been stored or an upload cancelled.

| `400 Bad Request`
| The request was malformed, e.g. a poster that is not an image.

| `401 Unauthorized`
| The request has no valid access token.

| `403 Forbidden`
| The user lacks the role the request requires.

| `404 Not Found`
| The requested resource does not exist, or the user may not see it.

| `409 Conflict`
| A chunk does not start where the upload stands, or someone else changed the resource.

| `413 Content Too Large`
| A poster or subtitle file is larger than allowed.

| `503 Service Unavailable`
| A service the request depends on, such as Spexregister, cannot be reached.
|===

[[roles]]
== Roles

Every endpoint requires an access token from the `fgv-spexflix` client with the `USER` client role.
Uploads also need `EDITOR` or `ADMIN`, exactly as in the xref:graphql-api-guide.adoc#roles[GraphQL API].

[[media_server]]
== Media server

The media server (``spexflix-media``, nginx) serves renditions, timeline thumbnails and subtitles from the HLS folder, on a hostname of its own (``API_MEDIA_BASE_URL``).
It never asks the API: every address is signed and expires.

``playback(videoId)`` in GraphQL returns ``<media base URL>/v/<expires>/<signature>/<uuid>/<generation>/master.m3u8`` with

[source]
----
signature = base64url(md5("<expires><uuid> <API_MEDIA_SIGNING_KEY>"))
----

valid for the video's duration plus four hours.
nginx's ``secure_link`` checks it for every file of that video: ``403 Forbidden`` for a wrong signature, ``410 Gone`` when it has expired.
The API and the media server share ``API_MEDIA_SIGNING_KEY``; its configuration is ``media/default.conf.template`` in https://github.com/bloomper/fgv-spexflix-deploy[fgv-spexflix-deploy].
Originals are never served.
